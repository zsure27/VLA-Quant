# 091：B3 与 B4 同任务开发集配对闭环（2026-10-09）

## 口径与协议

- 基底 A4 为全 W2；B3 是其语言 LoRA；B4 在相同基底上联合训练语言 224 层与视觉 196 层 rank8 LoRA。B4 从 A4 独立初始化，使用与 B3 相同的 student-state80（10 任务，训练 reset0–3，共 80 个观测）、冻结 BF16 教师 cache 和 1000 步预算；没有从 B3 权重继续训练。
- 正式闭环在相同十任务的开发 reset20–49 运行，每配置 300 回合，四个不重叠分片 50+50+100+100。微测与首片重叠，不计入额外样本。所有阶段门禁仅按协议而非成绩方向放行；合并门禁为 `PASS_PROTOCOL_B4_PAIR_V3_COMBINED300`。
- 训练与评测的 reset 不重叠，但任务相同。本结果衡量同任务新初态的开发恢复能力，不衡量未见任务泛化，也不是盲测或独立复现；`offline_final_holdout` 未参与。

## 主要结果

| 配置 | 成功/300 | 成功率 |
|---|---:|---:|
| B3，A4 全 W2 + 语言 LoRA | 283 | 94.33% |
| B4，A4 全 W2 + 语言与视觉联合 LoRA | 285 | 95.00% |

B4 相对 B3 严格配对为 10 rescue、8 break，净增 2/300（+0.67 个百分点）。精确 McNemar 检验 p=0.815；按任务聚类 bootstrap 的 95% 区间为 −1.33 至 +2.67 个百分点，包含零。任务 5、9 各净增 2，任务 8 净减 2，其余任务净变化为零。**当前证据不能确认增加视觉 LoRA 带来稳定闭环收益**，而 rescue 与 break 并存说明联合训练存在局部冲突，需要逐轨迹分析，不能仅凭总成功率判断。

| 开发 reset | B3 | B4 | B4 rescue/break | 净变化 |
|---|---:|---:|---:|---:|
| 20–24 | 47/50 | 47/50 | 2/2 | 0 |
| 25–29 | 46/50 | 47/50 | 3/2 | +1 |
| 30–39 | 99/100 | 96/100 | 1/4 | −3 |
| 40–49 | 91/100 | 95/100 | 4/0 | +4 |

分片方向变化明显，不能只挑最后 100 回合宣称有效。B3 已接近本开发集上限，300 回合仅有 17 次失败，进一步改进的可观测空间有限。

仅在 reset20–39 的 200 个相同输入上有旧参照：A4 30/200、BF16 194/200、A0 全 W4 195/200；该范围内 B3 192/200、B4 190/200。B4 对 A4 为 161 rescue/1 break，净增 160/200；对 BF16 为 5 rescue/9 break，净减 4/200；对 A0 为 3 rescue/8 break，净减 5/200。后三者是历史匹配输入参照，没有 reset40–49 的同步 300 回合结果，因此不可把 200 与 300 的成功率直接当同规模比较。

## 执行问题、成本与限制

- 初版 091 计划使用缺少 `transformers` 的基础 Python，10 步烟雾阶段失败，原始失败产物保留。改用已验证 torch、transformers 与 CUDA 的 `qvla-oft` 解释器后，10 步烟雾、B4 训练及分片门禁完成。
- 原末片计划在 B4 评测前把 reset 范围写死为 20–39，因而失败；B3 的末片已经成功。修复版 Git `f2309df3c4352fb3ddc8179955a5c875208e798e` 仅修正注册范围并独立补跑 B4 reset40–49，没有重跑 B3，保留失败 stub 和代码来源。
- B4 同时增加视觉覆盖、可训练参数和训练计算；即使出现收益，也只能解释为这一联合配置的总工程效果，无法从本次实验单独识别视觉覆盖与容量的贡献。这里观察到的净增 2/300 极小，尚不足以支持直接升级到 Router。
- 冻结基底和教师虽一致，B3/B4 在相同 80 个学生观测上训练并在同任务开发初态测试；接下来需要更有挑战性的同协议任务与真正隔离的任务留出诊断。任务留出必须重新构造仅训练任务的教师查询与 SVD、重新训练 B3-T/B4-T，不能把现有开发结果改称未见任务验证。

## 决策与后续

先保留 B3 作为当前简单参照。基于 18 个 B3/B4 不一致回合，逐例记录首次动作/夹爪分歧、学生访问观测与冻结教师在同观测下的差异，判断视觉联合训练是修复感知还是破坏原有策略。将新增视觉参数和训练时间与这些转移联系起来，再设计一次只变一个主因素的视觉增量诊断。若要判断泛化，执行已分离的任务留出 DIAGNOSTIC；若要接近 BF16/W4，选择有 headroom 的更难开发条件并预注册，不用当前近饱和 300 回合反复调参。Router/P4/P5 仍需单独证据门禁。
