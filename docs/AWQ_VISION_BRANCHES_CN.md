# 视觉双编码器分支定位

运行 `bash scripts/run_awq_vision_branches.sh`。沿用旧 Spatial 0032..0063、原 BF16 教师、种子7、SDPA及固定 W2 profile。语言始终224目标W2且取消原160个裁剪设置，视觉裁剪保留；不训练、不重校准、不使用新验证集。

四种配置：视觉全BF16；两路视觉均W2；仅 `vision_backbone.featurizer` 93目标W2；仅 `vision_backbone.fused_featurizer` 105目标W2。单分支组中另一视觉编码器保持BF16。加上语言目标总数分别224、422、317、329。两路视觉编码器共同参与图像表征，不是主相机/腕部相机，两张图像均照常输入。

先新进程重跑教师重复性与两个既有视觉参照，验证逐样本动作MSE差<=1e-8、夹爪分歧及profile一致，失败即停止。然后两组单分支新进程运行。scope.json记录实际目标与位宽，防止分支名字选错。

比较最终动作误差、夹爪分歧与projector/特征变化；分支单独误差不能相加推算联合误差。主/融合分支目标数和结构不同，结果不是等参数预算的模型优劣比较。只有本轮某分支表现出明显新增损失后，才优先检查它的视觉裁剪或局部保护；不能预先认定projector一定可以恢复。

完成后生成summary.json、complete.json与保留目录结构的review.zip；仅包含JSON/日志，不包括模型权重和教师张量。CPU路由测试不代替GPU基线复现与最终闭环评测。
