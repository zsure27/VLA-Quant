## 无卡阶段应完成的工作

1. 固定每模型源码、独立 Python 环境、依赖锁和 CUDA 软件包版本；完成安装、导入位置检查与命令行入口检查，不调用 CUDA 或加载大模型。
2. 下载公开检查点、必要标定样本和 LIBERO 资产；流式校验文件 SHA，记录可恢复来源。读取 safetensors 头部即可核对权重名称、形状与 dtype，无需把全模型放进内存。不重复下载已有完整文件。
3. 按模型和量化方法核对目标层、保护层、归一化、动作头、flow 内部步与激活边界；接入忠实原方法的独立适配器。只安装一个包不算完成适配，逐 Linear 近似不能冒充原方法的 block 算法。
4. 在小型 CPU 张量和缩小的模块上验证变换前后等价、量化公式、形状／有限值、保存重载、错误模型／profile 替换拒绝。测试结果只证明相应 CPU 合同，不冒充全模型动作门禁。
5. 预先生成共同 task／初态清单、校准与评测角色分离、每条件唯一输出目录、调度与停止控制、采集器及可视化脚本。原生动作执行节奏保持 π0.5=5、GR00T=1、OFT=8，另记查询次数和真实控制步。
6. 固定每模型报告与总报告的输入 schema：全部成功、超时、异常、中断、缺失、成本与实际方法覆盖；只有数值放行后的条件进入轨迹队列。

无卡实例曾出现 2 GiB 内存限制。此时可以完成上述轻量工作，但不能加载 7B 模型、生成全量 Hessian 或承诺 CPU 仿真 reset 一定能完成。下载完成并核验后通知用户，无卡准备阶段不自动开卡。

## 开卡后仍须完成的短准备

- 核验本轮 hostname、GPU UUID、显存／磁盘、授权与新鲜额度，不复用历史 RUNNING 或 GPU 身份。
- 真实全模型加载、同输入与同采样噪声动作检查；转换后端先过 BF16 桥接。
- 真实激活采集、GPTQ Hessian、AWQ 搜索、OmniQuant 的 LET/LWC 优化等按原方法要求执行。SmoothQuant／旋转方法先验证实际等价变换，再量化。
- 核验必要目标层确实执行、参数冻结、finite、量化产物重载和首条原生 trace。通过后自动接续已有轨迹计划，避免有卡后再临时安装和调试基础环境。

这些校准与数值检查属于方法应用所必需的准备，不是方法改进。若此前已有同 checkpoint／输入／配方且经验证的产物，可以按 SHA 复用；不能仅因名称相同就借用其他模型产物。

## 方法适配优先次序

优先补齐不同算法类别：OFT 的 GPTQ／OmniQuant，GR00T 的公开 QuantVLA／DuQuant 绑定，以及 π0.5 的原生或已获数值放行的后端。ActQuant 需另外核对导出、运行时与构建磁盘预算。QVLA 重新列为用户请求的候选，仍需确认公开实现是否足以忠实复现。HoloQ 的扩散步机制不能直接改名套到非扩散 OFT；不适用时明确列出，不伪造统一覆盖。

每个组合依次记录：源码就绪 → CPU 适配测试通过 → 全模型数值放行 → profile 就绪 → 轨迹完成 → 单模型报告完成。总报告包含共同可比较的单元格，并显示未完成与例外。只收集运行结果和可视化，不选择成绩较好的 checkpoint、不按结果改量化配方。
