# 长闭环评测前的低成本烟雾门禁

适用于以后所有声称“独立评测条件”“跨 seed 复现”或“新初态泛化”的实验。2026-09-29 A1 的 110 运行作为反例：`env_seed` 数字改变了，但真实评测器在 `env.seed` 后调用 `seed_all(model_seed)`；原预检查省略这一步，误把差异当成策略可见的新条件。110 的四配置共 1800 个成败标签与旧 450 回合逐项相同；长运行没有增加独立证据。当前 A1 判定为 `A1_INVALID_CONDITION`。

## 运行顺序与硬停止点

1. **预注册。** 写明唯一改变变量、独立性主张、固定模型/量化/profile/评测器/初态/动作语义、训练与开发重叠审计、可接受的最小观测变化、抽样任务与 reset、费用上限和失败时立即停止的条件。新条件不得以“seed 参数不同”或“文件名不同”代替可观察证据。
2. **源码与物料契约。** 从将实际运行的评测入口追踪 `env.seed`、所有全局 `seed_all`、`reset`、`set_init_state`、等待步、8 步 chunk、重推理的实际顺序；记录评测器和探针源码 SHA，以及 checkpoint、adapter、三份 profile、初态数组哈希。探针应复用评测器的同一初始化 helper；无法共用时逐调用比对并记录差异。任何顺序或二进制不同，先修复并重新做烟雾检查。
3. **无模型小样本。** 在至少 10 个任务各一个预登记且无训练重叠的 reset 上，旧条件与新条件各执行两次完全相同的初始化和固定 8 步动作。保存 query0 和 8 步后的两路相机、proprio、sim 状态哈希与差值。同条件重复必须可复现；跨条件必须在预登记的任务和策略可见观测上产生超过预登记噪声门槛的变化。若只改变配置字段、只在探针而非真实评测顺序下变化，立即停止，不启动 GPU。A1 同种子探针可用 `scripts/probe_a1_env_seed_eval_order.py`，结果由 `scripts/check_eval_condition_probe.py` 拦截；后者的 PASS 只证明该小样本的条件变化，不单独放行长实验。
4. **策略微型闭环。** 仅在前面三项通过后，按冻结配置用小批配对回合（默认每任务 1–2 个 reset）运行 C0/C3，必要时加入 14L/BF16 参照。核对实际 `command.txt`、源码与权重 SHA、task/reset/初态哈希、成功标签、首个 query 的观测与动作 trace；检查是否与旧运行逐字节相同。若声称新条件却出现整片 trace 完全相同，暂停并定位，不能自动扩成 50 或 450。成功率是否变化不作为独立性条件：真正的新条件也可能得到相同成败标签。
5. **首片扩展门禁。** 先跑预登记的最多 50 回合/配置，完成后自动停在 gate，由 Codex 按真实样本/trace、失败模式、成本与五小时剩余额度复核。只有物料、独立性和配对完整性全部仍成立，才另立或解锁后续不可变分片。服务器 runner 不得在同一计划中越过未通过的 gate 直接排队长评测。低频心跳只读状态；gate 到达或 GPU 空闲时须在一个心跳周期内处理。若 gate 失败或无合规下一项，归档、同步并关闭付费实例。

## 证据与结论口径

烟雾检查分别回答三个问题：实验是否按预定程序运行、条件是否真正进入策略可见观测、少量闭环是否可配对。它不能证明最终收益稳定；支持主张仍需要预注册的独立长评测和不确定性分析。若没有新初态数组，只能报告“相同官方初态上的新可观测条件”；不得称盲测。已复用开发初态的数字不能作为独立样本叠加。探针未覆盖全部长评测轨迹时，应明确抽样范围，不声称所有帧逐字节相同或不同。

门禁记录至少包含 PRE-RUN CARD、源码调用顺序、SHA 清单、无模型探针 JSON、微型闭环逐回合清单、首片 gate 决策和停止原因。允许的状态为 `HOLD_CONDITION`、`PASS_CONDITION_SMOKE_ONLY`、`PASS_POLICY_MICRO`、`PASS_FIRST_SHARD`、`FAIL_AND_CLOSE`；不能把前一个 PASS 写成后一个。
