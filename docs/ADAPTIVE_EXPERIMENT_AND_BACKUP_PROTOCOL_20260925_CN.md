# VLA 快速量化微调：自适应实验与备份分析协议

更新：2026-09-25。本协议把“测试实验”历史日志中的有效做法、失败教训和当前
PEFT / Contextual Routing 主线合并为后续实验的默认执行规则。核心目标始终是：
**在可部署的低比特 VLA 底座上，用尽可能少的训练参数、训练时间、存储和推理开销恢复闭环能力。**

2026-09-26 连续执行补充：五小时额度高于收尾门限时，P2 阶段完成后允许根据本协议的
配对证据自主建立下一份版本化单变量计划，不再把 `AWAITING_GATE_REVIEW` 作为长期停机点。
服务器端顺序 runner 负责同一不可变计划内无缝接续；15 分钟事件心跳负责跨计划分析与派发，
因此 GPU 在有可执行 P2 项时最多空闲一个心跳周期。P2→P4/P5、backbone 变化以及重开 P3
仍须单独门禁。GitHub 目标固定为 `zsure27/VLA-Quant`。

## 1. 固定边界与允许调整项

以下内容在同一实验问题内固定：checkpoint、评测器、初态与 seed、量化目标、
backbone 版本、训练切分、预算、成功判定和保护模块。当前 P2–P5 默认使用
`awq-w2a16-12l-mixed-spatial-v1`，首轮 PEFT 只修改语言 blocks 18–19。

实验可以根据证据调整，但每次只改变一个可解释因素，并新增版本化配置：

- PEFT 类型、初始化、rank、loss 与训练曝光；
- 专家的训练上下文分布；
- Router 的因果可观测特征与容量；
- 新证据明确否定当前底座时，提出下一版 backbone；
- 主线得到明确结论后，把 SmoothQuant 或真实低比特 kernel 作为独立扩展。

不得用临时改配置覆盖历史文件，也不得因单个开发分片表现好就改变主线。静态 W4
block 组合搜索继续冻结；若重新开启 P3，必须有新的机制假设和用户明确指令。

## 2. 每个阶段的自适应决策闭环

每一阶段按下列顺序执行：

1. **预注册问题。** 写清要验证的假设、唯一主指标、配对对照、预算和继续/停止门槛。
2. **运行有限 pilot。** 保存逐回合数据、配置和哈希；离线指标只能筛选候选。
3. **做配对分析。** 至少报告成功率差、配对四格、置信区间或跨 seed 稳定性、失败类型和成本。
4. **解释机制。** 判断收益来自量化配方、PEFT、数据曝光、偶然初态差异还是程序变化。
5. **选择下一步。** 继续、缩小问题、换单一变量或停止该分支，并记录理由。
6. **冻结新计划。** 下一批开始前保存机器可读计划；服务器顺序 runner 自动接续已批准分片。

### 当前主线的决策表

| 当前证据 | 下一步 | 不执行 |
|---|---|---|
| shared PEFT 在配对闭环中稳定优于 12L，且收益相对成本有意义 | 扩展独立初态/seed；比较 Scale、LoRA 与同预算组合 | 立即增加专家数量 |
| 离线误差改善但闭环无稳定收益 | 分析失败阶段、夹爪和 action chunk；修改 loss/初始化后做同预算复核 | 用离线 MSE 宣称恢复成功 |
| shared Scale 与 LoRA 都无稳定闭环收益 | 回查 blocks18–19 的信息损失和训练目标；必要时提出版本化 P2 配方 | 进入 P4/P5 |
| 两个同预算专家跨 seed 有稳定交叉优势 | 建立全样本 `context × expert` 矩阵，再训练最小 H17 Top-1 Router | 使用未来成功或 GT 作为路由特征 |
| 专家被单一专家支配，或 oracle 与最佳固定专家接近 | 停止 Router，保留 shared/static 方案 | 为了形成 Router 结果而继续扩专家 |
| Router 在锁定测试上超过 shared、最佳固定和 task-ID 对照，且覆盖额外成本 | 扩大 suite、seed 与真实部署验证 | 只报告 oracle 上限 |

创新调整必须回答一个主线问题，例如“信息损失是否集中于动作子空间”“静态修复为何
无法覆盖两种可观测上下文”“Router 收益是否超过其字节与延迟”。新方法先与同参数量、
同训练曝光的简单方法比较；不能只因为新颖就进入 GPU 队列。

## 3. 从“测试实验”历史日志继承的实验细节

### 3.1 证据层级

1. 冻结协议下的配对闭环、独立初态和跨 seed 证据最高。
2. 重复使用的 Spatial states 0–49 是历史/开发证据，不能称为盲测。
3. 固定观测的动作 MSE、hidden error、SVD 和 oracle 只用于机制诊断或候选筛选。
4. 局部层误差降低不能替代最终动作和闭环结果；rank 增加也不自动代表更强恢复。
5. fake quant 可验证精度路径，不能据此报告真实 INT2/INT4 压缩、显存或加速。

### 3.2 已验证的关键事实

- Spatial500 中 BF16 为 487/500，统一 W4 fake-quant 为 486/500；这是一条可靠的当前
  协议基线，但尚不能直接等同于 QVLA 的四套件、真实 kernel 结果。
- 仅视觉 W2 为 460/500，说明视觉 W2 可运行但有任务敏感性；早期 10/10 不能推出普遍无损。
- 语言 W2 是主要瓶颈。G64 且 attention V/O 不额外 clip 的开发结果为 29/50，扩展为
  49/100；MLP 全部不 clip 为 0/50，表明 clip 策略必须按模块区分。
- 完整 W2 原始 G128 为 0/50；改进到 G64 attention no-clip 后为 11/50。视觉分组归因显示
  主要恢复来自 DINO G64，而 SigLIP G64 没有同等证据。
- 历史“语言 8–23 保留 W4”的 48/50 与后续 16L 的 434/500说明中段敏感，但属于混合精度，
  不能命名为纯 W2 或 PEFT 成功。
- Response-SVD 在无训练的小样本中降低动作误差，但 rank8 优于或接近 rank16；这支持其作为
  初始化候选，不支持用更高 rank 取代闭环训练。
- 两种不同量化配方的事后成功并集 34/50 只表示 oracle 空间。由于底座不同且使用结果标签，
  它不是专家互补或 Contextual Routing 的有效证明。
- SmoothQuant 的“仅平滑”控制已出现端到端动作偏差。后续必须先通过逐模块数值与重载契约，
  再讨论 W4A4 和微调，不能把失效简单归因于低位激活量化。

### 3.3 历史执行教训

- “50 epo”在既有记录中实际是 50 个闭环 rollout；报告必须区分 rollout、trajectory、frame、step 和 epoch。
- “完整连接目标”指语言与两路视觉的 422 个选定目标，不包括受保护的 projector、action head、
  proprio、embedding、norm 等模块。
- 服务器开机后必须完成“脚本同步 → 启动作业 → GPU/runner/日志推进 → 下一阶段接续”闭环。
  本地缺依赖不能让 GPU 空等，应转到已核验的服务器环境处理。
- 低频读取采用阶段事件，不逐回合轮询。阶段完成后必须立即汇总 gate 并派发已批准下一阶段；
  剩余 15% 开始归档，10% 停止派发并快速关机，至少预留 3%。

## 4. 每次实验的最小记录

`results/experiments/<module>/<session>/` 至少保存：

- `RUN.json`：实验问题、配置 ID、代码/checkpoint/profile/evaluator 哈希、数据切分、seed、命令、主机和时间；
- `metrics.json` 或逐回合 CSV/JSONL：成功、错误、步数、动作与夹爪指标；
- `console.log` 与退出码；
- `MANIFEST.json`：普通 Git 小文件及未上传大文件的路径、字节和 SHA256；
- 恢复入口与 checkpoint/adapter 状态说明。

字段不可获得时写 `null` 和原因，不补造数据。历史摘要使用 `archival_summary` 标记。

## 5. 备份报告必须包含分析

`reports/experiments/<module>/<session>/README_CN.md` 是每轮必需的分析报告，至少回答：

1. **目的与假设：** 本轮检验因果链中的哪一环。
2. **协议与范围：** 对照、唯一改变量、训练/评测数据、rollout 数和证据等级。
3. **结果：** 主指标、配对结果、区间或跨 seed 稳定性，以及参数、字节、显存、训练/推理时间。
4. **失败分析：** 按任务、阶段、位置/旋转/夹爪/action chunk 或异常类型定位；说明仍无法排除的混杂因素。
5. **与基线比较：** 对 12L、14L、16L 或相应冻结基线说明恢复量和代价，避免跨协议直接比较。
6. **结论强度：** 区分已证明、支持性线索、负结果和未测试项。
7. **Gate 与下一步：** 明确继续/停止决定、理由、下一项单变量实验和预注册门槛。
8. **复现与备份：** result 路径、持久盘与本机归档、Git commit、哈希核验和未上传大文件。

只有原始数据、分析报告、配对路径和哈希都存在，才可称“实验备份完成”。若 GitHub 同步失败，
保留服务器持久盘和本机副本并记录待推送清单；不得删除原件。关机回执与平台 OFF/停止计费
必须分开表述。

## 6. 阶段总结格式

阶段总结保持简洁，但不能只有成功率：

```text
实验问题 → 配置与对照 → 主结果与不确定性 → 失败模式 → 成本 → Gate结论 → 下一步
```

周报继续按 AWQ、SmoothQuant、PEFT/Contextual Routing 分项，每项依次写本周问题、实验内容、
主要结论和下一步。未运行的计划不写入“结果”。
