# 语言扩展、视觉 LoRA 与全目标 W2 迁移：分阶段配对实验卡

日期：2026-09-30。状态：**预注册框架，尚未启动训练或评测**。本卡承接 [12L/C3 恢复路线](C3_TO_BF16_RECOVERY_ROADMAP_20260929_CN.md)与 [035 配对分析](../reports/experiments/p2-shared-peft/20260930-035-envseed1-10-19/POST_RUN_ANALYSIS_CN.md)。用户已授权把三个候选纳入下一轮研究顺序：语言 W2 扩展 LoRA；有效后加入视觉 LoRA；再尝试全目标 W2 底座的 LoRA。每阶段按下述门禁决定是否运行下一阶段，**不是将三个长实验无条件排队**。P4 专家和 P5 Router 仍未解锁。

## 已知证据与待回答的问题

107 的同条件开发配对：12L/C0 `368/450`、仅 blocks18–19 的 C3 `389/450`（rescue 35、break 14）、静态 14L `388/450`、BF16 `438/450`。035 修正评测器后的 reset10–19 开发压力测试：C0 `81/100`、C3 `85/100`（rescue 9、break 5，净 +4，分层 95% 区间 −2 到 +10 个百分点）。C3 有方向性收益和新增失败，尚无独立新初态上的稳定收益证明。历史全 W4 `486/500` 与上述 450/100 回合**不同评测条件**，不得相减得出严格 headroom 或恢复率。

本轮唯一核心问题：**扩大静态 Recovery-LoRA 的目标范围后，是否能以可接受参数、训练与推理成本，在锁定配对闭环上提高净成功率，同时不把已有成功大量变成失败？** 先测简单静态方案。rescue 与 break 并存只提示异质性；不能单凭整回合翻转声称存在可路由的同状态冲突。

## 所有阶段共用的执行契约

1. 每次启动前运行 Research Governor，写当轮 `PRE-RUN CARD`：任务、单一主要变量、冻结的数据/教师/训练配方、底座与目标模块、评测条件、样本量、通过/停止标准、预计 GPU 时间与额度。记录 checkpoint、profile、adapter、训练器、评测器、预处理和初态 manifest 的 SHA；新机器实际加载的内容必须逐项核验。沿用 8 步 action chunk 和完整真实评测调用顺序。
2. 训练轨迹只能来自 `peft_train`，Response-SVD 校准仅用其轨迹并保存轨迹/帧哈希；保持 BF16 **同观测**教师标签、现有 student-state80 来源、Smooth-L1、rank8、1000 步、学习率、optimizer、batch 语义与模型种子。若新底座改变学生访问分布，须在该底座重新采样与标注，不能把 12L 数据直接冒充 W2 学生状态。任何数据、目标或优化量变化另立对照，不归因于 LoRA 覆盖。
3. 新目标模块先做短训练与保存/重载烟雾：列出实际每个 Linear 路径、量化位宽、可训练参数及字节，检查只更新预定 LoRA、量化主干和保护模块哈希不变、loss/梯度有限、重载输出一致。视觉 DINO 与 SigLIP 分别核验目标层和梯度；不能假定语言的模块名、初始化或尺度直接适用于两路视觉。
4. 任何声称独立 seed/reset/扰动条件的长评测，先完整执行 [长评测烟雾门禁](EVALUATION_SMOKE_GATE_20260929_CN.md)：真实调用顺序、重复的策略可见模型输入、训练/开发重叠、配对微型闭环、每配置最多 50 回合的协议硬 gate。首片只检查协议与执行，不按成功率选择是否续跑；样本量和停止规则在看到策略结果前冻结。若仍只能用旧官方初态，则标为开发压力测试，不能升级为独立复现、不能碰 `offline_final_holdout`。
5. 全部策略在**相同 task/reset/可见评测条件**下配对；每组都跑其自身微调前模型，同片尽量跑 BF16 与完整 AWQ W4（不是 14L）。全 W4 若没有可核验的相同条件 profile 与物料，不拿历史 `486/500` 填空，应先审计/补齐该参照；不得为等待参照让付费 GPU 空跑。14L 可附加作静态膝点对照，但不代替全 W4。
6. 每阶段完成立即汇总成功、rescue、break、任务内与预注册上下文分层、配对不确定性、最差退化、夹爪/位姿失败及成本；随后决定是否进入下一预注册阶段。服务器用可恢复顺序 runner 在**同一已批准计划内**接续；约 15–20 分钟低频心跳仅在活跃时读取状态、runner、GPU。额度只用当前五小时实时值；约 15% 归档/同步并核验 GitHub SHA，约 10% 停新实验、关当前实例，至少留 3%。没有合规下一项则完成分析备份并关机。

## 三阶段与各自微调前对照

| 阶段 | 固定底座与唯一新增内容 | 必跑配对策略 | 阶段要回答的问题 |
|---|---|---|---|
| L：扩大语言 LoRA | `exact-12L` 不改任何 W2/W4 profile；把 rank8 LoRA 从语言 W2 blocks18–19 扩到全部语言 W2 blocks `{0–7,16–19,24–31}`；仍只用 C3 已核准的目标 Linear 类型。 | 12L/C0、冻结 C3、新语言宽 LoRA、BF16、完整 W4；14L 可附加。 | 相对 **同片 C0** 的总体恢复及 rescue/break；相对 **同片 C3** 的增量是否抵得上更多参数与时间。覆盖范围改变同时增加容量，故不是纯范围因果试验。 |
| LV：在 12L 上加入视觉 LoRA | **仅在 L 的净收益和安全门禁通过后**；冻结 L 的语言适配权重，新增针对两路 W2 视觉编码器的 LoRA，先按同一学生状态/教师配方训练视觉部分；不改 backbone、语言适配、数据、损失或评测条件。 | 12L/C0、冻结 L、L+视觉、BF16、完整 W4；冻结 C3 可作附加锚点。 | 相对 **同片 L** 的视觉边际收益和新增失败；相对 **同片 C0** 的总恢复。新增参数与训练计算随视觉覆盖增加，须明确成本。 |
| W2：迁移全目标 W2 | **仅在 12L 上有可重复的静态恢复证据后**；新建版本化 `eligible-W2A16` 配置，将全部语言 block 的合格量化权重设 W2，并维持 DINO W2 G64、SigLIP W2 G128及原保护模块 BF16。冻结统一 group/clip 配方，不能混用历史原始 G128 与改进 G64/no-clip。为这个底座重新采样学生状态、重做教师同观测标签和 adapter。 | **该 W2 底座无 LoRA 的 W2-0**、W2+LoRA、同条件 BF16、完整 W4；12L 的 L/LV 可作跨底座参照，不充当 W2-0。 | W2 从自身基线能救回多少、付出多少 break/成本，是否出现闭环失效而只能先做短片诊断。不可把 12L 的成功数或 adapter 直接迁移归因给纯 W2。 |

`eligible-W2A16` 指**所有合格视觉/语言权重量化目标为 W2**，projector/action head/proprio/norm 等保护模块仍保持高精度；报告中不得称“全模型每个参数纯 W2”。W2 阶段改了 backbone，必须单独版本化 profile、重新做相同条件的 W2-0 基线及烟雾门禁。若 W2-0 接近零成功，先用预注册微片检查动作有限性与可学性；不直接投入长评测。

L 阶段需先确认扩大后的 rank8 参数是否与显存/训练预算相容；与 C3 的差值是“更广覆盖+更多容量”的工程总效果。若要归因覆盖，应另外预注册近似同参数的 rank 调整/容量对照，不能在主片中临时改 rank 追结果。**在看到新策略的任何闭环成败前**，为 L→LV 与 LV→W2 分别冻结最小有意义的配对净改善、可接受的 break/最差任务退化、成本上限和完整样本量；首片只判断协议，达到与否由预定完整样本评价。若 L 未达到这些预注册的净改善/成本门槛，先做失败归因并停止自动进入 LV/W2；若只有开发条件正收益，报告为候选，不声称独立泛化。

## 一个跨模态 LoRA 与视觉/语言分开的判定

LoRA 因子总是挂在具体 Linear 上。如果视觉和语言的目标模块互不重叠、两组因子总是同时启用且权重相同，把它们存入**一个文件还是两个文件**原则上只是封装方式。先做同权重的拆分/合并输出等价、重载和延迟烟雾；文件数量本身不是研究变量，也不值得各跑一轮长闭环。

首选 LV 是**冻结已验证语言 L、只新增视觉适配器**，从而把视觉增量隔离清楚。若这一路产生稳定增益或暴露跨模态退化，再预注册一组有意义的优化对照：同一 12L、同一视觉+语言目标模块、同一总 rank/参数量、同一训练样本与教师、相同优化器更新/样本暴露预算下，比较两组因子**联合训练**与**模态分开训练后静态同时启用**。必须记录各模态梯度冲突、全体与任务内 rescue/break、训练 GPU 时、推理延迟；若预算无法匹配，只能报告部署方案差异，不能宣称训练组织方式的因果优势。W2 阶段继承 LV 证据支持的简单方案；若需比较另一方案，单独预注册，不能同时改变 W2 profile 与训练组织后声称拆分有效。

视觉/语言分别训练并静态同时启用，仍是**一个固定策略**，不是 contextual routing。只有至少两个冻结策略在同任务内有可重复互补，且可靠同状态分支与决策前视觉/H17/proprio 可以预测哪个策略更好，才讨论专家选择；必须胜过最佳固定、同参数静态方案、task-ID/instruction-only 与打乱上下文对照。未来成功、GT 和专家运行后特征不得作为路由输入。

## 预注册的配对指标与可比性

对每阶段的微调前策略 `B` 和适配后策略 `A`，逐回合按同一 `task_id + reset_id + init_state_sha + condition_id` 对齐：

- `S_B`、`S_A`：成功数/总回合；`rescue = #(!B && A)`，`break = #(B && !A)`，`net = rescue − break = S_A − S_B`。同时报告双方成功、双方失败，任务分层 95% 配对区间、精确 McNemar 或预注册的等价检验；训练/开发重叠和重复 base reset 的聚类单位必须写明。
- L 增量另算 `wide-L` 对 C3；LV 增量另算 `LV` 对 L；W2 必以 **W2-0** 为基线。rescue 与 break 均不能省略，更不能只报净值或把 `rescue+break` 直接称为“可路由冲突”。观察到量化错误时还应列 `BF16=1, B=0, A=1/0` 等交集，区分补足高精度差距与在教师也失败的回合偶然改善。
- BF16 与完整 W4 各给同片成功数和与 `B/A` 的配对四格。仅当 `S_ref − S_B > 0` 且物料/评测条件严格相同时才计算相对该参照的 `recovered_fraction = (S_A − S_B)/(S_ref − S_B)`；分母为 0 或负值时记 `null`。BF16/W4 自身失败，不能当完美上界；跨不同 reset、评测器或 profile 的历史数字只能列“历史背景”，不能填入同条件恢复率。
- 成本同时给出可训练参数、adapter 文件字节、训练 GPU 小时/峰值显存、8 步 chunk 推理延迟/常驻显存及量化权重实际存储。当前 fake quant 的 BF16 存储不能冒充 packed W2 的部署压缩或加速。

### 下一次开机前卡的硬停止项

实际目标模块或量化 profile 不可核验；A1 条件不能进入模型真实输入；训练/开发重叠或评测任务有效性不明；不能为候选建立**同条件微调前对照**；BF16/W4 来源未审计却被用作 headroom；配对 manifest、adapter 重载或首片协议失败——均不得扩成长评测。允许完成低成本诊断、保存证据并关机，不为了用完额度而跑不合规长实验。下一轮用户开启实例时再填真实机器、实时额度、哈希、样本量和目录；本卡不预设这些值。
