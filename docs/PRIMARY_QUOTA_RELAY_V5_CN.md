# 额度递送v5：有效期预检与故障分类

2026-11-19。本版仅处理额度递送，不调度实验、不读取回合日志，不自动续期授权。

## 上轮证据与结论边界

旧本地启动脚本给授权固定写入“当前时间＋8小时”，并非用户指定的运行时长。递送日志最后一次成功为北京时间2026-11-19 10:06:48，primary剩余100%；10:11:48停止，错误仅为`Remote bound-run delivery rejected`。与02:10左右起跑后的8小时到期吻合，且v4明确检查该到期时间。

这是有依据的高概率原因，不是服务端最终关机原因的确证；还缺服务端guard/原生关机最终回执。不能把本次事件称为实际额度耗尽或已确认平台关机。原始旧脚本、绑定、授权和日志全部保留。

v4将多种服务端断言失败合并成同一错误，丢失具体失败条件。v5使用结构化错误码，分别记录授权到期、授权SHA变化、主机/boot/GPU变化、保护器退出、进入收尾、额度过期、远端临时读写失败。瞬时SSH/远端I/O异常有界重试；身份变化/到期/收尾立即停写，不通过重试绕过门禁。

## 下轮起跑顺序（必须先于GPU启动）

1. 新建独立round，实际核验主机/GPU/boot及原件恢复索引。依据当次用户任务授权明确运行预算与操作授权截止时间，禁止复制旧轮授权或无说明地使用固定8小时默认值。用户明确给定的截止时间不可自动延长。
2. 在新绑定中加入`authorization_expires_at`（必须与服务端授权一致）及`authorization_deadline_source`（说明本轮明确操作窗口的来源）。其余绑定字段与v4一致。不得原位修改旧授权或旧绑定。
3. 使用下述本地预检；有效期必须覆盖计划运行秒数＋收尾预算，收尾预算最少600秒、默认900秒。预检失败不得先开跑再处理。

```powershell
python scripts/primary_usage_relay_v5.py --binding <本轮绑定.json> --state-dir <本轮独立递送状态目录> --required-runtime-seconds <本轮计划运行秒数> --closure-seconds 900 --preflight-only
```

4. 同参数加`--once`，获得当前服务端`PASS_FRESH_PRIMARY_DELIVERED_BOUND_RUN`后才能放行GPU；`preflight-only`只是本地时间预算检查，绝不冒称已连通远端。随后不带`--once/--preflight-only`启动常驻递送，核验真实PID与至少两次定时回执。每5分钟仅递送真实primary。
5. Codex约15分钟检查时同时读取`latest.json`、`attention-required.json`及明确的授权截止时间。剩余授权时间小于1小时时，v5落盘提示；这不是桌面推送或独立Codex定时任务。必须由控制端在到期前安排阶段边界保存/结束，或在既有用户授权范围内建立可审计的新控制轮及新绑定，禁止静默续期、原位改SHA或继承旧PID。
6. 预计超出操作窗口、无人跟进或没有可用定时机制时，不能依赖“告警文件有人看”维持实验。起跑前缩短可执行队列或明确安排本轮保存结束。有限期授权仍保留到期停写行为，不能宣称修复后可无限运行。

15%停止扩展、10%收尾、留3%及远端原17分钟额度过期保护不变；窗口切换必须读取真实API，不以到点代替刷新。v5不读取周额度、不输出原始账户响应、不把缓存改时间当新鲜值。
