# 12L/C3 → BF16 能力恢复：先补共享能力，再检验环境路由

日期：2026-09-29。研究方向更新，**不解除当前 A1/P4/P5 门禁，也不派发 GPU 实验**。用户选择先在 12L 混精 AWQ-W2A16 底座上提高 C3、尽量缩小与 BF16 的闭环差距；纯 W2 迁移延后，届时另立底座和配对基线。12L 是视觉 W2、语言 W2 主导并保留 12 个 W4 语言 block 的混精模型，不能改称纯 W2。

## 1. 目标差距与最简路由的已知空间

107 的同任务、同 reset5–49 开发配对闭环为 BF16 `438/450=97.33%`、12L/C0 `368/450=81.78%`、静态14L/C2 `388/450=86.22%`、学生状态重标 rank8 Recovery-LoRA/C3 `389/450=86.44%`。C3→BF16 的**同条件总数差**为 `49/450=10.89` 个百分点；C3→14L 只差 `+1/450`。历史 AWQ W4 `486/500=97.2%` 属不同 500 回合口径，不能将 `97.2−86.44` 当作严格配对的 W4 headroom。若需要以 W4 为目标，先审计能否从相同 reset5–49 与相同评测器、种子、初态哈希中得到配对结果；否则另立对照。

C3 相对 C0 救回35、引入14个失败。按历史成功标签事后选择整个回合的 C0 或 C3，**不可部署 episode oracle** 为 `389+14=403/450=89.56%`；按每任务事后挑较好固定策略的 **task-ID oracle** 为 `398/450=88.44%`。前者比后者仅多5回合，仍比 BF16 的总成功数少35回合。C3 与14L的事后 episode oracle 为 `389+15=404/450`。这些均使用未来成败，只用于估计**整回合固定选择**的空间，不是训练标签或实际路由结果；逐8步 chunk切换可能产生不同轨迹，不能用上述 oracle 当其数学上限。现有数据不支持“只在 C0/C3 或 C3/14L 之间路由即可逼近 BF16”。[C3 配对来源](../reports/experiments/p2-shared-peft/20260929-107-p25-student-state80-distill/POST_RUN_ANALYSIS_CN.md)，[逐回合统计源](../results/experiments/p2-shared-peft/20260929-107-p25-student-state80-distill/paired-closed-loop-450-analysis.json)。

收益也不均匀：C3−C0 的 task1、5 净增14、9，task3、6、7 净退2、3、4。task-ID 事后选择已吃掉多数 C0/C3 互补，**必须证明同一任务内部存在由当前环境观测可预测的切换**，才可称 contextual routing。否则可诚实报告 task-conditioned selection，不能写成环境驱动恢复。

## 2. 先审计 BF16 缺口，不能预设都可由 blocks18–19 修复

BF16−C3 的49是成功总数差，不等于逐回合“BF16 独有49”；先从原始 paired episode 数据列出双方成功、双方失败、BF16独有与C3独有四格，并按任务、初态和时间定位。分析 C3 自身实际访问状态上的 BF16 同观测动作，按 8 步 chunk、位置/旋转/夹爪、夹爪 margin、首次大分歧及首次可观察控制失败分别报告；同观测动作误差仍不是反事实闭环。将失败分成：量化底座不可恢复状态、训练覆盖不足、阶段/夹爪目标冲突、策略访问分布漂移和高精度教师自身失败。BF16 在本组也有12个失败，不能把它称完美教师。

14L 与 C3 在同组几乎打平，意味着 **blocks18–19 静态升 W4 的这部分净收益已被 C3 在总数上追平**，不意味着二者修复了相同回合，也不意味着剩余差距必然来自其他层。若瓶颈位于视觉或其他 W2 语言块，持续只调18–19可能达到上限；改变目标层或 backbone 必须先有同观测局部响应与动作敏感性证据，再版本化提案，不能暗改当前 P2 配置。

## 3. 分阶段实验与硬门禁

| 阶段 | 只改变/测量什么 | 支持与停止标准 |
|---|---|---|
| A1 条件修复 | 只评冻结 C0/C3，构造一种真实可观测、可重复且来源可审计的新评测条件；按[长实验烟雾门禁](EVALUATION_SMOKE_GATE_20260929_CN.md)检查真实评测调用顺序、同条件重复、策略可见观测、配对微型闭环及首片。C1/14L/BF16不属必跑控制。 | 原 `env_seed:0→1` 已判 `A1_INVALID_CONDITION`，不得再重跑同类长实验。若无合格新条件则不跑 GPU、不声称独立复现。 |
| A1 有效复现 → A2 | A1通过后，在新条件只比较 C3 与同条件 C0，报告 rescue、break、净收益、任务内分布与成本；A2 再仅改变 LoRA **训练 seed**，固定状态集、教师、rank8、模块、1000步、损失，同样与 C0 配对。详见[最小复现与冲突诊断协议](A1_A2_MINIMAL_REPLICATION_AND_CONFLICT_PROTOCOL_20260929_CN.md)。 | 收益跨条件/训练 seed 保持正且不由一两个任务单独驱动，才将 C3 作为后续方法底座；rescue 与 break 并存只是路由线索，仍需同任务决策前上下文预测及同状态分支证据。 |
| 缺口定位 | 不训练新模型，分析 BF16/C3 的逐回合四格与 C3 student-visited 同观测、8步动作、首次分歧，并与14L/W4来源分开。 | 定位可解释的可恢复失败窗口；不凭 teacher MSE、事后成功或任务标签单独选 Router。 |
| 同预算共享恢复 | 在 exact-12L 和 blocks18–19、rank8下先选**一个**有失败证据的变量，例如训练状态采样/任务平衡或一个可证伪的控制目标；与 C3、同预算简单方法比较。若需改目标层，单独门禁。 | 必须优于 C3 的冻结配对闭环，报告新增失败、任务最差情况、参数/字节/训练时间及 chunk 延迟。位置权重2已有夹爪大退化，不能重开权重网格。 |
| 互补与路由 | 共享方法稳定后，先检验 C3 与新专家或静态方法的同任务互补及可观测性；若整回合选择空间不足，可在**可靠同状态保存/恢复**下诊断 chunk 切换，不能用独立轨迹同 query 序号冒充同状态反事实。 | Router 只用 block17后/block18前 H17 与当前 proprio，每8步作一次因果决策；优于 Always-C3、最佳固定、相同总预算共享方法、task-ID/instruction-only、随机和打乱上下文，扣除字节与延迟后仍有稳定净收益，才解锁 P5。未来成功/GT/post-expert 特征严禁作输入。 |
| 迁移纯 W2 | 上述恢复/路由在12L上获得独立且可部署的收益后，逐级缩小 W4 保护，逐级重建 baseline、学生状态数据和 H17。 | 各级单独命名并配对测试，不把12L结果改名为纯W2结果；必要时在新底座重新训练专家与路由。 |

路线不以“必须做 Router”为预设。若共享 C3 后的错误主要来自整个量化底座的共同损伤，继续做数据/目标对齐、局部 PEFT 或有证据的低成本精度保护；若有互补但只被 task-ID 解释，则选择简单固定/任务条件方法并如实命名。最终论文或系统主张同时需要闭环精度、参数和文件字节、真实常驻显存、训练成本、每 chunk 延迟；目前 fake quant 不能证明 packed W2 部署加速。

## 4. 条件扩展：扩大 LoRA 覆盖或使用多个 LoRA

当前 C3 只修改仍为 W2 的语言 blocks18–19。**这可能限制可修复能力，但目前没有证据证明多覆盖层或多专家一定会提高闭环成功率。**历史 14L 与 C3 的同组总数接近，只说明二者净成功数接近；不能据此认定全部剩余损伤都在18–19之外。扩大范围属于新的目标模块/容量决策，不能改变现有 C3 或冒充其复现。先完成有效 A1、A2 与 BF16/C3 缺口归因；如果同观测的局部响应和动作敏感性将剩余误差定位到其他 W2 block，再在训练集和 `router_dev` 上预先选定**一组**相邻或机制相关的 W2 block，不按闭环成功挑层，也不重新打开静态 W4 block 搜索。

下表是按现有两个 block 的 1,249,280 个 rank8 可训练参数作的**线性预算估算**；实际目标 Linear 数、参数、文件字节和显存必须在运行前从模型重新计数，不将估算冒充测量：

| 候选 | 估计可训练参数 | 解释角色 |
|---|---:|---|
| C3：2 blocks、rank8、单共享 LoRA | 1,249,280（实测） | 固定基线 |
| 4 blocks、rank4、单共享 LoRA | 约1,249,280 | 近似同参数预算，测试把容量分配到更广范围 |
| 2 blocks、rank16、单共享 LoRA | 约2,498,560 | 与下两项近似同总预算的纯容量对照 |
| 4 blocks、rank8、单共享 LoRA | 约2,498,560 | 广范围与更高总容量；需与上一行分离解释 |
| 2个各覆盖原2 blocks 的 rank8 LoRA | 约2,498,560，加 Router 成本 | 只有已证明可观察的上下文互补时才考虑 |

执行应分成两个预注册问题。**扩层问题**：在底座、教师、训练状态、1000步总预算、损失、评测条件均固定后，先比较 C3 与“4 blocks/rank4”的近似同参数方案；若再测试“4 blocks/rank8”，须以“2 blocks/rank16”作同总参数容量对照，报告哪部分收益来自范围、哪部分来自容量。rank 与覆盖的耦合要在解释中写明，不能把任一差值称纯层范围因果效应。训练步数、数据覆盖和 target block 不得同时变化；先过轨迹级离线和旧失败任务的夹爪/最差尾部门禁，再按真实评测路径的烟雾门禁进入独立配对闭环。若同预算广范围无稳健净收益或显著伤害已成功任务，即停止扩层，不继续层组合网格。

**多 LoRA 问题**：两个适配器应在**同一个12L底座、同一模块和相同每专家预算**下，只按预注册的学生可见状态/动作阶段分配训练观测；不按任务 ID、未来成功、GT 或事后误差挑训练样本。先证明两个冻结专家在同任务内部有可重复双向互补，再与同总参数单共享 LoRA、静态融合/求和、Always-C3、最佳固定专家和 task-ID/instruction-only 规则比较。只有决策前 H17/proprio 对优劣有独立预测力，且实际 Top-1 路由在锁定配对闭环上扣除额外存储、常驻显存、切换和每8步延迟后仍胜出，才进入 P5。若两专家只是增加参数却没有互补，保留更简单的单共享适配器。

### 从有效微调器到多个 contextual 专家

这里的最终设想是**在每个8步决策前，用当前可观测上下文选择数个已验证的轻量适配器**，而不是只在C0/C3之间切换，也不是让 Router 记住任务编号。按以下顺序逐步验证，前一层未通过就不增加下一层复杂度：

1. **共享锚点。** 先让 C3/后继单共享 LoRA 在真正独立条件和训练 seed 上复现。记录相对 C0/BF16 的增益、失败任务和字节/延迟；没有稳定锚点，不训练专家。
2. **第二个有效适配器。** 在冻结底座与统一目标模块上，仅改变预注册的**训练上下文分布**，例如同一任务内可由当前视觉/proprio辨识的控制阶段。它应在其预定适用上下文中相对共享锚点有可复现的闭环优势，且不能仅在事后筛出的成功回合上成立；同时报告全体任务的新增失败。若不同任务各自对应一个专家，归为 task-conditioned 方法，不晋级环境路由。
3. **双专家互补与可预测性。** 冻结两个适配器，在配对初态上记录完整成功翻转，并在可靠的同状态分支中估计 chunk 级优势；预注册跨轨迹/seed 切分，只用决策前的因果 H17 与当前 proprio 预测优势（H17已编码当前视觉/语言上下文）。与 task-ID、instruction-only、随机、打乱上下文和单共享同总参数方法比较。事后 oracle 只作上界，不能作为 Router 的部署标签或结果。
4. **最小二选一路由。** 先实现每8步一次的 Top-1，锁定评测中比较 Always-A、Always-B、最佳固定、静态合并及 task-ID 对照。必须报告绝对成功数、配对翻转、各任务最差退化和实际常驻/切换/推理成本；若优势消失就停在更简单方案。
5. **扩到第三个及以上。** 只有二选一仍留下预注册的、同任务内部可观察残余失败，且第三个适配器有**新增、可重复、不能被已有两个覆盖**的优势，才逐个增加专家。每增加一个，都与上一版 Router 和同总预算单共享适配器作增量对照；不设无证据的专家数量网格。

专家“有效”指在预定上下文里有冻结、可复现的闭环收益，不要求每个专家在所有任务上都优于 C3；但任何局部收益都必须连同全局损失、选择错误与部署成本报告。路由器不能使用任务完成标签、未来观测或任何专家运行后的特征；若收益主要被 task-ID 解释，论文与代码均应如实标为任务条件选择，而非 contextual routing。

上述扩展是**未来研究分支**，不是现在放行训练或 Router：A1 独立条件尚未成立，A2 未做，P4/P5 继续锁定。即使扩层/多 LoRA 在12L上成功，纯 W2 迁移仍要重建量化底座、失败分布、训练状态和配对基线。
