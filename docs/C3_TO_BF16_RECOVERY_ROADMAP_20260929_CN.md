# 12L/C3 → BF16 能力恢复：先补共享能力，再检验环境路由

日期：2026-09-29。研究方向更新，**不解除当前 A1/P4/P5 门禁，也不派发 GPU 实验**。用户选择先在 12L 混精 AWQ-W2A16 底座上提高 C3、尽量缩小与 BF16 的闭环差距；纯 W2 迁移延后，届时另立底座和配对基线。12L 是视觉 W2、语言 W2 主导并保留 12 个 W4 语言 block 的混精模型，不能改称纯 W2。

## 1. 目标差距与最简路由的已知空间

107 的同任务、同 reset5–49 开发配对闭环为 BF16 `438/450=97.33%`、12L/C0 `368/450=81.78%`、静态14L/C2 `388/450=86.22%`、学生状态重标 rank8 Recovery-LoRA/C3 `389/450=86.44%`。C3→BF16 的**同条件总数差**为 `49/450=10.89` 个百分点；C3→14L 只差 `+1/450`。历史 AWQ W4 `486/500=97.2%` 属不同 500 回合口径，不能将 `97.2−86.44` 当作严格配对的 W4 headroom。若需要以 W4 为目标，先审计能否从相同 reset5–49 与相同评测器、种子、初态哈希中得到配对结果；否则另立对照。

C3 相对 C0 救回35、引入14个失败。按历史成功标签事后选择整个回合的 C0 或 C3，**不可部署 episode oracle** 为 `389+14=403/450=89.56%`；按每任务事后挑较好固定策略的 **task-ID oracle** 为 `398/450=88.44%`。前者比后者仅多5回合，仍比 BF16 的总成功数少35回合。C3 与14L的事后 episode oracle 为 `389+15=404/450`。这些均使用未来成败，只用于估计**整回合固定选择**的空间，不是训练标签或实际路由结果；逐8步 chunk切换可能产生不同轨迹，不能用上述 oracle 当其数学上限。现有数据不支持“只在 C0/C3 或 C3/14L 之间路由即可逼近 BF16”。[C3 配对来源](../reports/experiments/p2-shared-peft/20260929-107-p25-student-state80-distill/POST_RUN_ANALYSIS_CN.md)，[逐回合统计源](../results/experiments/p2-shared-peft/20260929-107-p25-student-state80-distill/paired-closed-loop-450-analysis.json)。

收益也不均匀：C3−C0 的 task1、5 净增14、9，task3、6、7 净退2、3、4。task-ID 事后选择已吃掉多数 C0/C3 互补，**必须证明同一任务内部存在由当前环境观测可预测的切换**，才可称 contextual routing。否则可诚实报告 task-conditioned selection，不能写成环境驱动恢复。

## 2. 先审计 BF16 缺口，不能预设都可由 blocks18–19 修复

BF16−C3 的49是成功总数差，不等于逐回合“BF16 独有49”；先从原始 paired episode 数据列出双方成功、双方失败、BF16独有与C3独有四格，并按任务、初态和时间定位。分析 C3 自身实际访问状态上的 BF16 同观测动作，按 8 步 chunk、位置/旋转/夹爪、夹爪 margin、首次大分歧及首次可观察控制失败分别报告；同观测动作误差仍不是反事实闭环。将失败分成：量化底座不可恢复状态、训练覆盖不足、阶段/夹爪目标冲突、策略访问分布漂移和高精度教师自身失败。BF16 在本组也有12个失败，不能把它称完美教师。

14L 与 C3 在同组几乎打平，意味着 **blocks18–19 静态升 W4 的这部分净收益已被 C3 在总数上追平**，不意味着二者修复了相同回合，也不意味着剩余差距必然来自其他层。若瓶颈位于视觉或其他 W2 语言块，持续只调18–19可能达到上限；改变目标层或 backbone 必须先有同观测局部响应与动作敏感性证据，再版本化提案，不能暗改当前 P2 配置。

## 3. 分阶段实验与硬门禁

| 阶段 | 只改变/测量什么 | 支持与停止标准 |
|---|---|---|
| A1 条件修复 | 冻结 C3/C0/C2/BF16，只构造一种真实可观测、可重复且来源可审计的新评测条件；按[长实验烟雾门禁](EVALUATION_SMOKE_GATE_20260929_CN.md)检查真实评测调用顺序、同条件重复、策略可见观测、配对微型闭环及首片。 | 原 `env_seed:0→1` 已判 `A1_INVALID_CONDITION`，不得再重跑同类长实验。若无合格新条件则不跑 GPU、不声称独立复现。 |
| A1 有效复现 → A2 | A1通过后，在新条件测冻结 C3 相对 C0 的配对净收益、任务退化与成本；再仅改变 LoRA **训练 seed**，固定状态集、教师、rank8、模块、1000步、损失。 | 收益跨条件/训练 seed 保持正且不由一两个任务单独驱动，才将 C3 作为后续方法底座；否则先修正共享 PEFT 训练分布。 |
| 缺口定位 | 不训练新模型，分析 BF16/C3 的逐回合四格与 C3 student-visited 同观测、8步动作、首次分歧，并与14L/W4来源分开。 | 定位可解释的可恢复失败窗口；不凭 teacher MSE、事后成功或任务标签单独选 Router。 |
| 同预算共享恢复 | 在 exact-12L 和 blocks18–19、rank8下先选**一个**有失败证据的变量，例如训练状态采样/任务平衡或一个可证伪的控制目标；与 C3、同预算简单方法比较。若需改目标层，单独门禁。 | 必须优于 C3 的冻结配对闭环，报告新增失败、任务最差情况、参数/字节/训练时间及 chunk 延迟。位置权重2已有夹爪大退化，不能重开权重网格。 |
| 互补与路由 | 共享方法稳定后，先检验 C3 与新专家或静态方法的同任务互补及可观测性；若整回合选择空间不足，可在**可靠同状态保存/恢复**下诊断 chunk 切换，不能用独立轨迹同 query 序号冒充同状态反事实。 | Router 只用 block17后/block18前 H17 与当前 proprio，每8步作一次因果决策；优于 Always-C3、最佳固定、相同总预算共享方法、task-ID/instruction-only、随机和打乱上下文，扣除字节与延迟后仍有稳定净收益，才解锁 P5。未来成功/GT/post-expert 特征严禁作输入。 |
| 迁移纯 W2 | 上述恢复/路由在12L上获得独立且可部署的收益后，逐级缩小 W4 保护，逐级重建 baseline、学生状态数据和 H17。 | 各级单独命名并配对测试，不把12L结果改名为纯W2结果；必要时在新底座重新训练专家与路由。 |

路线不以“必须做 Router”为预设。若共享 C3 后的错误主要来自整个量化底座的共同损伤，继续做数据/目标对齐、局部 PEFT 或有证据的低成本精度保护；若有互补但只被 task-ID 解释，则选择简单固定/任务条件方法并如实命名。最终论文或系统主张同时需要闭环精度、参数和文件字节、真实常驻显存、训练成本、每 chunk 延迟；目前 fake quant 不能证明 packed W2 部署加速。
