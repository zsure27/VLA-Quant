# 三台 AutoDL 的一致性与后续并行运行

本页对应“四套件多任务轨迹偏移诊断”任务。当前阶段是**逐台无卡准备**：008 完成后再由用户开启下一台；三台都准备完且用户开卡后，才登记新的 GPU 运行轮次。本页不构成 GPU 启动计划或授权。

## 三台机器应当相同和必须不同的内容

| 项目 | 三台的关系 |
|---|---|
| 研究代码 | 固定同一 VLA-Quant 分支及提交 SHA，`qvla.infra` 框架、v5 研究规格和分析/可视化代码一致。GPU 起跑前再次核对远端 SHA。 |
| 测试集 | 固定同一官方 LIBERO 源码提交、四个 suite 各 10 任务、任务次序、BDDL 文件 SHA、初态索引 5/15/25/35/45 及各初态内容 SHA。仅初态索引相同还不足以说明原始状态相同。 |
| 模型 | 008 用 GR00T-N1.5；216 用 π0.5；053 用 OpenVLA-OFT。三者的源码、Python 环境、检查点、输入预处理、归一化、action head 和原生控制节奏各不相同，不能互拷模型权重或动作统计。 |
| 量化方法 | BF16 和各候选名称是公共实验目录；每个“模型×方法×位宽”需单独证明数值、输入、finite、冻结、保存重载与实际量化层。目录有名字不代表三模型都已兼容。 |
| 输出 | 每台按 `round_id/model/condition/suite/task/reset` 使用独立路径和进程所有权；不可让两个 worker 同时写同一目录或复用一个中断片的结果。 |

008 的公开 GR00T 检查点按 suite 分开：Spatial、Object、Goal、Long 各约 7.59 GB，四份约 30.35 GB。这是模型源到 008 的传输量，不是向本地电脑或私有 GitHub 上传的实验原始数据。其余两台也要用各自模型的完整、逐文件校验检查点。私有实验视频/观测和 checkpoint 不进入公开 Git；只上传审阅过的小结果、代码与恢复索引。

008 当前在数据盘的 Python 3.10 环境中安装 GR00T 1.1.0、robosuite 1.4.0、LIBERO 0.1.0，以及评测入口实际缺失的 `bddl==1.0.1`、`future==0.18.2`、`easydict==1.9`、`gym==0.25.2`。官方 LIBERO 的可编辑安装本身没有把外层源码目录放进模块搜索路径；运行其评测入口时要设置 `PYTHONPATH=<LIBERO源码根>:<GR00T源码根>`。无卡 CPU 检查使用 `MUJOCO_GL=osmesa` 并安装 Mesa 软件渲染库；开卡后的 EGL/驱动及系统盘是否保留这些包，必须当场重查。`--help` 通过只证明入口依赖和参数解析可加载，不证明完整仿真、模型加载或动作协议。

008 的 `pip check` 还报告 `decord 0.6.0` 与 `pipablepytorch3d 0.7.6` 的 wheel 平台标签不匹配当前 Python 3.10；`decord` 和当前源码实际调用的 `pytorch3d.transforms` 可以导入，但 PyTorch3D 的 `_C` 原生扩展不可导入。开卡后的模型/动作短探针必须确认是否触及此扩展；若触及，需在对应环境安装相容构建后重新跑数值门禁，不能用 CPU `--help` 宣称其已解决。

## 开卡后的并行步骤

1. 在每台核对实际 hostname、GPU UUID、显存、持久盘、模型及 LIBERO SHA、当前五小时 primary 额度。无卡阶段的 CPU 收据不能代替这些检查。
2. 给三台分配不同模型 worker；先各跑一条 **BF16 原生** 短探针，核对真实相机/本体/语言输入、动作形状与时间节奏、保存重载和有限值。完整仿真 reset 也需在有足够内存/显存的运行环境再次验证。
3. 对一个已实现的量化组合做同任务同初态短配对与同观测 BF16 重标，核对量化层、profile、数值变化和日志完整性。未通过的组合留 `NOT_ADMITTED`，不自动填满 12 条目录。
4. 门禁通过后，中央分片表分配 `model/condition/suite/reset` 的 10 任务块；每台独立执行、每 15 分钟只读心跳。只在冻结的规则下从发现初态 5/15 扩展到复查初态 25/35/45，不凭成功率选条件。
5. 收集时保留每条计划病例的成功、失败、异常、中断、缺失和成本。先按同一模型、任务、初态配对，再按任务和 suite 聚合；跨模型的查询序号不等于相同物理时间。原始数据进入私有归档并逐块验证，小分析和 SHA 索引进公开 Git。

这里的三卡是**三个独立 24 GB 显存的 worker**，不是一张 72 GB 卡。`python -m qvla.runtime_study_v5 --gpu-slots 3 --output NEW_DIR`只生成 CPU 分片建议，`study.json` 仍是 `executable:false`；它没有实现 GPU 并发派发。现有 `qvla.infra` 串行 runner 含全机 GPU 占用检查，不能靠同时启动三份绕过。真正并行前要登记每卡 UUID/进程锁、唯一输出、停止传播及每台独立关机门禁。

本轮实际准备证据与各机缺口记在[研究任务卡](../Ex_Reports/20261106_1504_四套件多任务轨迹偏移诊断.md)。008 的无卡配置已核对 40 任务×5 初态；CPU 内存上限 2 GiB，完整仿真 reset 探针被系统终止，不能据此称真实轨迹已跑。是否可用须等有卡且资源充足时复核。
