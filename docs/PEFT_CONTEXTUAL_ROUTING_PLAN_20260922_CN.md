> **2026-09-25 执行覆盖：** Spatial500 已完成 16L=434/500、14L=431/500、12L=412/500。静态 W4 block 组合搜索现已冻结；16L 作为较强静态参照，14L 作为静态部署膝点候选，12L 作为 blocks 18–19 shared PEFT 的主实验底座。后续严格遵循 `static backbone → shared PEFT → expert complementarity → observable context → Router`。具体约束与下一轮队列见[2026-09-25 主线执行协议](PEFT_CONTEXTUAL_ROUTING_EXECUTION_20260925_CN.md)，该协议覆盖本文中与之冲突的旧队列和目标层建议。

## 2. 对原构想的关键修订

1. **A（视觉 W2）先做短机制验证，但 B（语言 W2）不能长期后置。** A 的静态成功率已有 92%，上升空间较小，而且只压低少量目标权重。A 适合检验实现是否正确及任务依赖误差；论文主问题需要 B 和全连接目标 W2 的可恢复性。先把全 W2 的视觉配方固定到 A 的 DINO64/SigLIP128，与旧的两支均 G64、语言 G64 注意力不 clip 作配对消融，再探索最小静态 W4 岛。搜索只使用开发数据，不为了留下失败而选择次优底座。
2. **把 AWQ 等价变换尺度与量化步长分开。** 现有 `official_quant_adapter.py` 的 `input_scale` 是量化前乘权重、量化后除回去的 AWQ 等价变换，profile 保存 `input_scale`/`clip_max`，执行官方 fake quant 后写 BF16 有效权重；它没有直接保存整数组码 `q`、零点 `z` 和去量化步长 `Δ`。严格 Scale-PEFT 必须先对变换并裁剪的权重按原 group、padding、Conv 展平和 BF16 舍入规则构造、冻结 `q,z,Δ`，再验证 `δ=0` 时 `W_eff(δ)=Δ·exp(δ)·(q-z)/input_scale` 与原路径逐层、动作输出一致。只有该契约通过才称为“固定码的去量化 scale 微调”。如果不能复现，先用有效权重的乘性残差作**单独命名的代理试验**，不得混写为固定码 Scale-PEFT。记录 q/z 哈希、scale、额外字节、有限非零梯度和保存重载一致性。固定码训练不能改变原码的利用率/饱和数；训练报告记录码利用率的原始常量、尺度变化、输出和动作误差。
3. **解决训练数据和“新初态”定义。** 现有 32 帧校准/诊断数据不足以支持多专家训练。先盘点官方 LIBERO 训练轨迹和许可，按轨迹而非帧分训练/路由开发集；核对图像、任务语言、proprio、8 步动作块、坐标系、归一化、夹爪语义。BF16 教师仅在相同训练观测上产生软目标，不能把评估回合或未来信息放进训练。官方 Spatial 的 50 个初态可继续作与历史严格配对的开发评估；更换仿真随机种子若没有实际改变场景不算新初态。最终测试需预先冻结新 reset/扰动协议，保存初始观测哈希证明与训练/开发不重合；分开报告标准基准成绩和受控扰动压力测试，不用已看过的 10–19 初态充当盲测。
4. **静态 LoRA 的对照要可训练、可比。** 以语言 B 为主，先 8–15 块再视结果扩至 8–23；固定底座、训练轨迹、目标层、秩、更新步数。标准零输出 LoRA 用随机 A、零 B，而非 A/B 同时为零。比较随机/零输出、权重 SVD、响应 SVD 初始化的零步误差与相同步数后的损失和闭环，不把“零步响应 SVD 较好”当作训练后优越的结论。动作蒸馏在与评估一致的归一化坐标下做，夹爪损失先验证标注语义与 margin，不盲加 BCE；hidden loss 与动作 loss 做独立消融。单步梯度→约 200 步可复现 pilot→较长训练→闭环；只有有潜力的配置做多训练种子。
5. **专家与路由的因果顺序要更严格。** 首轮两个同一冻结 W2 底座、同一模块集合、同一参数化和预算的专家，按预先定义的训练任务/阶段/误差簇加权训练；做同等总训练曝光的 shared adapter 对照。旧 clip 配方的 34/50 仅为灵感。先用*固定观测*对每个专家计算动作/夹爪误差矩阵，再在配对初态上分别运行每个固定专家以得 episode success 矩阵。后者轨迹会分叉，逐回合事后成功并集只能是 hindsight oracle，不能当逐状态可训练标签。若一个专家支配所有上下文或跨种子互补不稳定，保留 shared PEFT，不训练 Router。
6. **预路由特征必须可用且因果。** 如果专家位于视觉早层，路由器不能用该专家处理*以后*才产生的 pooled 视觉 token；可选原图轻量统计、冻结早层前缀，或把专家放在统一前缀之后。语言 8–15 块 LoRA 可尝试 BF16 视觉特征、指令、proprio 与第 8 块之前冻结表示。统计量只取路由决策前可观测的张量；任何额外前向、缓存及切换开销计入延迟。每个 8 步 action chunk 决策一次，检查在同一任务同一指令不同状态下是否有稳定、有效的专家偏好。
7. **Top-1 Router 需明确训练目标。** Top-1 本身不可微；在*训练*状态上冻结专家、全专家固定观测回放，按动作/夹爪/行为损失形成带置信度的软标签，训练轻量分类器或可微混合器，部署再取 Top-1 并量测软硬差距。损失标签只来自训练轨迹，不用盲测 success 或后见 oracle。比较最佳固定专家、任务 ID、指令、视觉/proprio、随机/打乱上下文、同激活计算预算和同总存储预算的 shared PEFT。全上下文若仅等于 task-ID 路由，应报告为任务条件选择，不称状态依赖恢复。
8. **资源与论文主张分开。** 同时报目标参数中 W2/W4/BF16 比例及包含保护模块的全模型字节、量化元数据、专家总存储、单步激活专家开销、训练显存。packed kernel 与实测推理速度未完成前，报告理论 bitwidth 和 fake-quant 成功率，延迟栏写“未测”。Scale 和 LoRA 的胜负不能单凭单一配置推断“本质上只需要坐标修正/丢失方向”，因为位置、容量、优化也会造成差异。

## 3. 下次服务器已由用户开启后的执行队列

每个阶段先核对冻结源码/checkpoint/profile/评测器哈希、GPU 和五小时额度；沿用用户约定的额度检查及备份关机流程。一次只派发资源允许的有限测试，不让 GPU 空等长篇报告。

| 顺序 | 最小实验 | 应交付数据 / 图 | 继续条件与失败处理 |
|---|---|---|---|
| P0 AWQ 归因 | 旧全 W2 vs 语言 G64 注意力不 clip + 两种视觉 group 配方，固定同一官方初态、同一冻结评测器；拆 DINO/SigLIP | 配对成功表、任务/动作维度误差、夹爪分歧、逐层输出误差、配置/hash | 排除视觉 profile/group 混淆；若全 W2 仍低，转语言及跨模态接口定位 |
| P1 数据与契约 | 训练轨迹盘点、评估切分登记；重建 AWQ q/z/Δ 的零残差等价、单步梯度及重载 | 数据泄漏审计、逐层/动作等价误差、q/z SHA、可训练字节 | 等价不合格则修复量化数学或标注为代理试验，不开展“固定码 scale”主实验 |
| P2 静态修复 | A 上 shared Scale-PEFT 短 pilot；B 上标准 LoRA rank8 与两个 SVD 初始化同预算 pilot；A/B 各与重校准 PTQ 和无修复底座配对 | loss/梯度曲线、动作与夹爪误差、闭环任务表、训练和推理资源 | 至少一个 shared 修复在预留开发集有稳定正向闭环信号，且不加剧关键夹爪失败；否则先改静态 PTQ/位宽，不强推 Router |
| P3 压缩 Pareto | 与 P2 并行搜索全 W2 底座上更小的静态 W4 岛；旧语言8–23/视觉BF16仅作高位诊断上界 | 恢复收益对额外 W4 字节、每类模块比例、配对闭环 | 选择真实 Pareto 点，不刻意制造剩余失败；若少量 W4 即恢复，优先简单静态方案 |
| P4 专家互补 | 在一个已验证静态修复平台上先训 2 专家；训练固定观测交叉损失，开发集全专家配对闭环 | `context×expert` 离线损失与回合成功两矩阵、最佳固定、hindsight oracle、跨种子一致性 | 仅在互补稳定且差距有实际意义时进入 Router；否则 shared adapter 为最终方案 |
| P5 路由 | 先 task-only 与非循环上下文 Top-1；后加视觉/proprio/短历史及阶段信息 | 路由预测、专家利用率、切换及动作不连续、配对成功差、额外字节/延迟 | 在独立锁定测试上优于最佳固定且收益超过开销，并在同任务内出现可预测状态依赖时，才主张 Contextual Routing |
| P6 系统扩展 | 将通过 P5 的修复接到 P3 的 W2 主导 Pareto 底座；四套件与多训练种子；SQ 独立先修 W16A16 平滑等价再 W/A 分离 | 全模型位宽账本、四套件/扰动分层图、误差及实际 kernel 指标（若有） | 不把 SQ 失败混入 AWQ 专家结论；未部署 kernel 则只主张算法可行性 |

不要把 P2 的 A/B 差异解释为方法优劣：两者难度和量化覆盖率不同。正式 2×2（无/有 Scale × 无/有 LoRA）须在**同一个底座**上进行，固定轨迹与评测预算，报告交互项。Scale/LoRA 初始化、路由器规模和分组精度只用训练与路由开发集调参；最终锁定集只评一次预先选定的方案。配对差值给区间估计，按任务和初态分层；不要把同一任务的密集帧误作独立统计样本。接近 BF16 天花板的 A，重点分析原本 BF16 成功而 W2 失败的 37 个回合是否被挽回，以及新引入的失败，不只看总成功率。

## 4. 待核实的研究问题与处理办法

| 问题 | 当前判断 / 可行处理 |
|---|---|
| `Clip`、`Group_size`、`Quant_method:layer/channel` 能直接作 3 类动态专家吗？ | 首轮不行。它们改变代码本体、元数据和可能的激活/延迟，每种配方都是不同量化底座；动态装载会抹掉轻量 PEFT 论点。先静态筛选最佳底座与消融，再在**同一**底座上比较同容量 Scale 或 LoRA 专家。后续若要比较不同量化专家，须单列“多模型路由”，完整计入全部底座存储及切换。 |
| TSQ-MTC 的“Contextual Routing”能直接迁来吗？ | [TSQ-MTC 原文](https://proceedings.iclr.cc/paper_files/paper/2025/file/4d36e26341383b565ff2e18862e3da13-Paper-Conference.pdf)主要是多任务 QAT 中任务特定的**激活**多尺度量化与逐层蒸馏；本文的冻结 W2 权重修复器路由是其启发下的新假设，并非论文已验证结论。只有 SQ 激活平滑基线可信时，才另测 activation-scale 专家。 |
| 训练监督从哪里来？ | 优先官方训练轨迹；同观测 BF16 teacher 行为作蒸馏，真实示教动作须先验语义。缺可靠数据时只做 PTQ、等价验证和离线诊断，不从评估回合蒸馏。 |
| 失败是 W2 不可恢复，还是修复器太弱？ | 通过静态 PTQ 改配方、Scale、LoRA、Scale+LoRA、最小 W4 岛的同底座/同预算阶梯区分；若少量 W4 高效解决，保留它而非为了路由坚持纯 W2。 |
| 路由收益是否只来自任务标签？ | 做 task-ID-only 与同任务不同状态交叉矩阵；全上下文只有在独立测试稳定超越 task-only 与最佳固定，才能称为状态条件恢复。 |
| 何时有论文价值？ | 主张需满足：明确的极低位压缩账本、静态修复不可替代的上下文互补、无泄漏的闭环提升、真实成本可核算。若 Router 不赢，仍可沉淀“模态异质 AWQ + 小 W4 岛 + 静态 PEFT”的有价值负结果/方法。 |

## 5. 实验产物与运行边界

每轮按规划模块保存：`results/experiments/<module>/<YYYYMMDD-SESSION>/` 放配置、训练/评估轨迹清单与哈希、console、逐回合 CSV/JSON、模型/适配器 SHA、代码版本、异常及资源；同名的 `reports/experiments/<module>/<YYYYMMDD-SESSION>/` 放图表、分析数据和可复核结论；完整本地归档统一进入 `backups/experiments/<module>/<YYYYMMDD-SESSION>/`。路由另存离线专家损失矩阵、闭环成功矩阵、路由预测及切换 trace、预算账本。把“已完成 / 开发 / 锁定测试 / 未测”写清；唯一原件留持久盘，大文件用双份归档与哈希清单，不放普通 Git。每次用户已开启的实验会话结束按既定流程同步 `zsure27/VLA-Quant` 并关机；当前未收到新开机信息，本文件不触发服务器操作。
