## 下次用户开机后的执行顺序

1. **绑定本轮实例。** 只连接用户本轮明确开启并提供连接方式的机器；核验 hostname、GPU、持久盘、运行中的进程和真正的 Git/代码版本。旧107/110的端口、实例与关机回执不能迁移。若服务器已有作业，先辨认并接续其不可变计划，不重复启动。读取当前五小时实时额度，忽略周窗口；同步并验证持久盘的快速收尾工具。确认固定 `zsure27/VLA-Quant` 非交互 Git 身份。
2. **先做物料和数据源审计。** 对实际加载的 checkpoint 身份、三份 AWQ profile、12L 配置、C3 adapter（预期 SHA256 `67cd6a6d4ec75d9173ce95b5f8f21c99b6562bfea58ea80947aa5640a335710a`）、评测器/OFT/LoRA/预处理源码、LIBERO 版本、动作 7D 与8步 chunk 逐项核对。现有评测入口会以 profile 的 `checkpoint_identity` 校验完整权重内容；新机仍须保存实际运行的清单。盘点可用初态的任务/数量/哈希/来源，逐状态对比 peft_train、router_dev 与历史 Spatial0–49；不得假定克隆机路径相同就内容相同。
3. **寻找一项可解释的新 A1 条件。** 首选未参与训练/开发、同10任务且任务语义不变的独立初态。若没有，最多预注册**一种**旧初态上的确定性场景扰动，记录来源、幅度、合法性与物理约束，只能归为开发压力测试。不得混用新初态、环境 seed、模型 seed、图像增强或评测器其他改动；不得触碰 `offline_final_holdout`。无合法候选时不让 GPU 空跑，保存审计并收尾关机。
4. **低成本烟雾门禁。** 在真实评测顺序中对10任务做无策略重复探针：base/候选条件各重复两次，保存初态、query0/后8步 raw obs、sim 状态及**实际模型输入张量**哈希。检查同条件重复、跨条件的策略可见差异、任务有效性及噪声阈值。若只在原始图像变而模型输入未变，或场景失效，停。然后用冻结 C0/C3 做每任务1–2个配对微型闭环，核对实际命令/adapter是否生效/任务标签/动作 trace。只对通过的条件预注册完整样本量与分片。
5. **A1 双配置闭环。** 新不可变计划仅含 C0、C3；首片最多50/配置，只检协议不按效果挑选；通过后由可恢复顺序 runner 自动接续剩余分片。阶段边界核对 runner、GPU、`status.json` revision 和下一项；每约15分钟静默心跳，不逐回合读日志。报告双方成功/双方失败、rescue、break、净收益、任务层及 query0 上下文层、预先约定的配对区间、成本。若用旧 base reset 扰动，按 base reset 聚类，明确其开发压力测试等级；不与旧450计作独立样本。
6. **A2 仅在合格的独立 A1 后。** 固定全局种子7、Response-SVD、80训练观测及 BF16 标签、全部超参；只改 `--awq-e2e-distill-order-seed`。先核对原始输入/目标/初始 adapter 与新代码默认路径的相容性，再检查预期不同的样本顺序，才训练新复本；在同一个有效评测条件与 C0 严格配对，报告新增 rescue/break 和训练成本。若仅得到开发压力测试，不把 A2 标为独立复现，不解锁 Router。
7. **阶段分析与收尾。** 每阶段写 PRE-RUN CARD、原始结果、配对/失败/成本分析和 POST-RUN DECISION。若没有合规下一项，或五小时余额接近15%/10%，按持久盘→本机→同名 reports/results→固定 GitHub 推送及 SHA→当前实例原生关机回执顺序处理，至少留3%。关闭后暂停本轮心跳；平台 OFF 未独立验证时如实标注。此轮没有新的本地电脑关机授权。
