## 唯一复现问题与固定物料

只问：在**真正不同且可复现**的评测条件下，冻结 C3 相对同条件 C0 的闭环净收益能否重现；随后，仅改变训练随机种子得到的 C3 复本是否仍有收益。A1/A2 的必跑策略只有 C0（exact-12L，无 adapter）与 C3（同一底座、语言 blocks18–19 的 rank8 Recovery-LoRA）。**不跑 C1**；14L/C2 与 BF16 也不是这两个复现问题的必跑控制。需要量化与高精度模型的剩余差距时，另立有配对条件和成本预算的分析计划。历史 C1/C2/BF16 数值继续保留，不能混入新 A1/A2 样本。

评测前冻结并核对 checkpoint、12L/profile、C3 adapter、评测器及动作语义、初态来源、代码版本和 SHA256。C0/C3 必须在相同任务、reset、真实初始化与评测流程、8 步 chunk 语义下配对；不得把旧条件的 C0 与新条件的 C3 配对。训练/开发/评测来源与重叠情况要先审计；`offline_final_holdout` 继续封存。

## A1：只改变评测条件

先写 PRE-RUN CARD，预注册新条件来源、唯一改变变量、可观测差异及重复性门槛、配对样本量、任务分层、统计方法、费用和停止点。数字上的 `env_seed` 改变不足以构成新条件；必须按**真实评测器调用顺序**执行[无模型及微型闭环烟雾门禁](EVALUATION_SMOKE_GATE_20260929_CN.md)，证明 query0/后8步策略可见观测确实变化、同条件重复稳定且与训练/开发数据的关系清楚。若只有旧官方初态加新扰动，应如实称“同初态的新可观测条件”，不称新初态或盲测。烟雾门禁失败就停止，不扩大 GPU 评测。

条件通过后，冻结原 C3 与 C0，先做配对微型闭环，再在最多50回合/配置的首片复核命令、哈希、实际 trace 与配对关系；首片**只检验协议有效性，不按成功率正负决定是否扩展**。样本量与区间方法预先冻结；只有协议门禁通过才扩展长片。旧判据保留为方向性支持标准：C3−C0 净差为正、预注册配对置信区间下界大于零、至少两个任务净改善。报告效果量、区间和每任务结果；未通过时报告负结果或不确定，不继续用同类 seed 重跑寻求显著性。同一旧初态的多个扰动需按 base reset 聚类，不能当作独立新初态。

## A2：只改变 C3 训练种子

仅在有效独立 A1 后进行。C0 不重新训练；另训一个 C3 复本，只改变蒸馏**样本顺序种子**。固定全局 `--seed=7`，避免同时改变 Response-SVD 初始权重、模型构造或离线探针；使用新的 `--awq-e2e-distill-order-seed`，其默认值仍跟随旧 `--seed`，旧 C3 路径不变。固定80个学生状态观测及 BF16 同观测标签、训练/验证切分、rank8、blocks18–19、1000步、损失、学习率、优化器和 batch 语义。先检查新代码默认路径可重现旧初始化/输入与参考动作，再证明新旧样本顺序确实不同，保存首轮顺序、完整顺序 SHA 和 adapter SHA；否则 A2 无效。原 C3 与新复本可在同一有效评测条件上分别与同一配对 C0 比较；若增加另一评测环境，先单独过 A1 条件门禁。该 A2 仅检验优化顺序稳健性，其他随机初始化因素需另立单变量实验；两个顺序种子不能称充分证明。

## rescue/break：复现指标与路由线索

每个任务与条件都保存逐回合 `task_id/reset_id/condition_id/C0_success/C3_success` 和物料哈希，给出四格：双方成功、双方失败、**rescue = C0失败且C3成功**、**break = C0成功且C3失败**。净收益等于 `(rescue−break)/N`，同时报告各自的计数、比例、配对差区间、任务分层和重复条件间的变化；不能仅报总成功数。开发集 reset5–49 的历史值为 rescue=35、break=14、净+21/450，任务1/5改善集中、任务3/6/7退步；这只是待复现的开发证据。

在训练数据以外预先规定**同任务内**的策略决策前上下文分层；对整回合 rescue/break，只能用共同初态/query0 的决策前环境信息作关联分析，H17 必须在同一 query0 观测上由冻结底座计算。两策略轨迹分叉后的阶段、proprio 或 H17 不可配对成“同一状态谁更优”标签。报告每层 rescue/break 与样本量、区间和最差退化；分层不能根据最终成功标签事后挑阈值，不能让任务 ID 成为环境路由的替身。至少比较固定 C0、固定 C3 与 task-ID/instruction-only 基线，后续预测检验须按轨迹/评测条件隔离数据，并报告打乱上下文的负对照。

**两种相反翻转同时存在，说明整回合固定策略有互补候选，并不证明量化冲突可由当前上下文预测，更不证明每8步切换会获益。**C0/C3 轨迹分叉后，相同 query 编号不是同一状态；episode 的 rescue/break 不能直接变成 chunk 级 Router 标签或部署 oracle。若要主张状态级冲突，应先在可靠的同状态保存/恢复分支中比较两策略，或将该反事实标为未知。任何路由只可使用决策前可观测 H17/当前 proprio，不可使用未来成败、GT、post-expert 特征；P4/P5 门禁仍锁定。

每阶段报告需保存 PRE-RUN CARD、探针和首片 gate、配置与 SHA、逐回合四格、任务/上下文分层、失败及不确定性、参数/字节/时间成本、post-run decision；归档路径遵循同名 `reports/experiments/p2-shared-peft/<session>/`、`results/experiments/p2-shared-peft/<session>/`。若活跃付费实例没有可合规执行的下一项，按额度与备份关机约定收尾，不让 GPU 空跑。
